API reference

The names below are exported by using DeepCompartmentModels, except ImplicitError, which is used as DeepCompartmentModels.ImplicitError. The package also re-exports Lux.jl, Optimisers.jl, Accessors.jl, Distributions.jl, OrdinaryDiffEq.jl and SciMLSensitivity.jl, whose documentation applies to those names.

Some functions have no docstring yet; they are listed in tables with a one-line description so that this page still covers the whole interface.

Data

An Individual holds the covariates, observation times, observations and dosing events of one subject. A Population is a vector of individuals of the same type. See the data tutorial.

DeepCompartmentModels.Individual — Function
Individual(id, x, t, y, callback, ::Type{T}=Float32; kwargs...)

Constructor to create Individuals. This is the primary object holding data in DeepCompartmentModels.jl. Each Individual contains information on the covariates x, time points of interest t, and the observations y. Individuals also contain a callback that stores information on the relevant clinical interventions. This function recognizes the appropriate subtype based on its arguments.

Arguments

  • id <: Union{Integer,AbstractString}: the id linked to this subject.
  • x: Covariate values.
  • t: Relevant time points.
  • y: Observations.
  • callback: Clinical interventions used in the differential equation.

Keyword Arguments

  • u0: initial values to use for the differential equation.

Examples

If a Vector is provided for the covariates, time points, and observations, construct a BasicIndividual.

julia> Individual("test", rand(3), rand(4), rand(4), CallbackSet())

Models

DeepCompartmentModels.DeepCompartmentModel — Type
DeepCompartmentModel{P,M,E,S}

Model architecture originally described in [janssen2022]. Originally uses a neural network to learn the relationship between the covariates and the parameters of a system of differential equations, which for example represents a compartment model.

Arguments

  • problem::AbstractDEProblem: DE problem describing the dynamical system.
  • model: Model to use for the prediction of DE parameters or DE components. The package focusses on the use of neural networks based on Lux.jl.
  • error: Error model to use for likelihood calculations.
  • target: The index of the partial derivative for the prediction of the dependent variable. Default = 1.
  • sensealg: Sensitivity algorithm to use for the calculation of gradients of the parameters with respect to the DESolution. Defaults to ForwardDiffSensitivity(). For a UniversalDiffEq with at least 512 parameters (DeepCompartmentModels.UDE_ADJOINT_MIN_PARAMS) the default is GaussAdjoint(; autojacvec = ReverseDiffVJP(false)), which is much faster for large networks (about 5x at ~1,000 and 50x at ~4,000 parameters in a benchmark). Its gradients differ from the forward sensitivities by about 2e-4 (relative, solver tolerance level), and Lux logs a one-time warning about ReverseDiff.TrackedReal inputs. Pass sensealg = ForwardDiffSensitivity() to use forward sensitivities for any size. InterpolatingAdjoint(; autojacvec = EnzymeVJP()) is faster still but takes longer to compile.


[janssen2022] Janssen, Alexander, et al. "Deep compartment models: a deep learning approach for the reliable prediction of time‐series data in pharmacokinetic modeling." CPT: Pharmacometrics & Systems Pharmacology 11.7 (2022): 934-945.

Objectives

An objective is a callable objective(model, data, ps, st) that returns the scalar to minimise.

DeepCompartmentModels.VariationalELBO — Type
VariationalELBO(idxs)

Optimise the fixed and random effects by minimizing the ELBO:

ELBO(ps) = Ez~q[p(y | z) + p(z) - q(z)] = Ez~q[p(y | z)] - KL[q(z) || p(z)]

Arguments

  • idxs: Parameter indexes of ζ for which to estimate random effects.

Keyword arguments

  • mean_field=false: Boolean to indicate whether to use the mean field approximation.
  • path_deriv=true: Boolean to indicate whether to use the path derivative estimator by Roeder et al. (2017).
  • natural=false: Boolean to indicate whether to use natural gradient descent based optimisation using NaturalGradientOptimisers.jl.

Calculates the gradient with respect to the logjoint instead of the full ELBO.

Setting up and training

fit trains a model with an Optimisers.jl rule. It is a thin wrapper around setup, gradient and Optimisers.update; the first tutorial writes that loop out explicitly.

StatsAPI.fit — Method
fit(obj, model, population, opt; rng, T, epochs, callback, ad, parallel, batchsize, nbatch, init_sigma, params, ...)
fit(obj, model, population, opt, ps, st; rng, epochs, callback, ad, parallel, batchsize, nbatch)
fit(obj, model, population, opt_state, ps, st; rng, epochs, callback, ad, parallel, batchsize, nbatch)

Optimise the parameters of model by minimising obj on population with the optimiser opt. Each epoch is one gradient step on the whole population. fit is a thin wrapper around setup, gradient and Optimisers.update:

ps, st = setup(obj, rng, model)
opt_state = Optimisers.setup(opt, ps)
for epoch in 1:epochs
    st = update_state(rng, st, obj, model, population, ps) # only does something for VariationalELBO
    ∇ = gradient(obj, model, population, ps, st; ad, parallel, batchsize, nbatch, rng)
    opt_state, ps = Optimisers.update(opt_state, ps, ∇)
end

When ps and st are not provided they are created with setup (using rng). Passing ps and st allows continuing a previous fit. Instead of an optimiser rule (e.g. Optimisers.Adam(1e-3)) a previously returned opt_state can be passed.

Supported objectives are the fixed effect objectives (MSE, SSE, LogLikelihood) and VariationalELBO (without natural = true). Models with a UniversalDiffEq only support the fixed effect objectives.

Arguments

  • obj: Objective, e.g. SSE(), LogLikelihood(), VariationalELBO(idxs).
  • model: A DeepCompartmentModel.
  • population: A Population.
  • opt: An Optimisers.AbstractRule or an optimiser state returned by an earlier call.
  • ps, st: Parameters and state as returned by setup.

Keyword arguments

  • epochs = 100: Number of gradient steps.
  • callback: Called after each step as callback(epoch, loss), where loss is the objective evaluated at the parameters used for that step. Defaults to printing. Use callback = (args...) -> nothing to silence it. The loss is a by-product of the gradient computation and costs no extra solve.
  • T = Float32: Element type of the parameters created by setup (Float16, Float32 or Float64). Only when ps and st are not given, otherwise the types of ps are used.
  • rng = Random.default_rng(): Random number generator used by setup (when ps and st are not given) and, for VariationalELBO, to resample the noise of the variational posteriors every epoch. Pass a seeded rng to make a fit reproducible.
  • ad = AutoEnzyme(; mode = set_runtime_activity(Reverse)): Automatic differentiation backend, passed to gradient. Use AutoForwardDiff() for forward mode differentiation. AutoZygote() (after import Zygote) is only advised for in-place UniversalDiffEqs with large networks, see gradient.
  • parallel = false, batchsize = nothing, nbatch = nothing: Passed to gradient. parallel = :individual solves individuals on separate threads (start Julia with -t auto), parallel = :batch does so per mini-batch of batchsize individuals (at most) or in nbatch mini-batches; set at most one of them (default batchsize = 16). The batches are drawn using rng.
  • init_sigma, params and, for VariationalELBO, init_omega and scale: passed on to setup, see there. Only when ps and st are not given.

Any other keyword throws an ArgumentError.

Returns

(opt_state, ps, st). When interrupted (Ctrl-C) the current state is returned.

Example

dcm = DeepCompartmentModel(UniversalDiffEq(1), Lux.Chain(Lux.Dense(1, 16, tanh), Lux.Dense(16, 1)))
opt_state, ps, st = fit(SSE(), dcm, population, Optimisers.Adam(3f-3); epochs = 500)
predict(dcm, population[1], ps, st)

DeepCompartmentModels.value_and_gradient — Function
value_and_gradient(objective, model, population, ps, st; ad, parallel, batchsize, nbatch, rng)

Compute the value of objective and its gradient with respect to ps, in a single pass. Returns (loss, ∇). The gradient has the same structure as ps; for VariationalELBO the entries of ps that are not differentiated (omega) are nothing.

Arguments

  • objective: Objective function.
  • model: A DeepCompartmentModel.
  • population: A Population.
  • ps: Model parameters.
  • st: Model state.

Keyword Arguments

The individuals are divided over the batches as evenly as possible. If neither is set, batchsize = 16. See create_batches.
  • rng=Random.default_rng(): Random number generator used to assign individuals to batches when parallel=:batch.

Automatic differentiation

gradient, value_and_gradient and fit take an ad keyword with an ADTypes.jl backend:

backenddescription
AutoEnzyme(; mode = set_runtime_activity(Reverse))the default. Reverse mode with Enzyme.
AutoForwardDiff()forward mode with ForwardDiff. Fast for models with few parameters.
AutoZygote()reverse mode with Zygote. Opt-in: needs import Zygote. Only advised for in-place UDEs with large networks.

Notes:

  • Enzyme cannot yet differentiate through the differential equation solvers in forward mode, so AutoEnzyme(; mode = Forward) throws an error. Use AutoForwardDiff() for forward mode.
  • The first gradient call of a Julia session compiles the Enzyme code for the objective and sensitivity algorithm that is used. This takes up to a minute (the ODE solver machinery is most of it); later calls are several times faster than with Zygote (which was used before). A model with a different layer type or activation function costs a few extra seconds, a wider network with the same layer types is free. This cannot be moved to package precompilation: Enzyme compiles the differentiated function just in time and a precompiled package image would store a pointer that is invalid in the next session, which segfaults (Enzyme.jl#681). AutoForwardDiff() compiles in a few seconds.
  • AutoZygote() is only advised for in-place UniversalDiffEqs with large networks. Enzyme cannot yet differentiate the adjoint sensealgs (GaussAdjoint, ...) of in-place problems, whereas Zygote can, so such a model needs DeepCompartmentModel(UniversalDiffEq(n; inplace = true), network; sensealg = GaussAdjoint(; autojacvec = ReverseDiffVJP(false))) together with ad = AutoZygote(). In general, a large network should be written as an out-of-place UDE (the default) and differentiated with Enzyme, which is faster. Zygote is slower, compiles for a while, and does not support VariationalELBO(path_deriv = false) with full-rank posteriors.
  • Gradients with respect to parameters that are not used (such as the infusion rate I of a UniversalDiffEq) are zero.

DeepCompartmentModels.MultiHeadedBranch — Function
MultiHeadedBranch(covariate_idx, neurons, heads; activation, init_bias).

Convenience function for creating branches in Lux models. Constructs a neural network containing a single hidden layer connecting to multiple independent layers in parallel specified by heads. This way, the covariate effect shares a similar base, but can still learn independent effects for each head. All hidden layers contain the same number of neurons. It is advisable to use at most 2 covariates as input to the model to facilitate interpretation.

Arguments:

  • covariate_idx::Union{AbstractVector{<:Int}, Int}: Index of the covariate(s) to use in the branch.
  • neurons::Int: The amount of neurons in the hidden layer.
  • heads::Int: The number of independent heads.
  • activation: Activation function to use in the hidden layer. Default = swish.
  • init_bias: Initialization function of the bias parameters. Default = ones32. Can help with improving the initial estimates.
